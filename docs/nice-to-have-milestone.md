# AGS3D Nice to Have & Future Ideas

This document collects aspirational features and ideas that are not on the
critical path for any current milestone. Each entry is a stub. None of these
are planned for implementation until they are:

1. Promoted to a dedicated milestone with a full spec.
2. Given a concrete use case inside an actual game being made with AGS3D.
3. Assessed for feasibility and design.

## IDEA-01 — Puppet 2.5D Character Type

### Summary

A third character visual type (`type = "puppet"`) that renders a character as
a layered set of 2D sprite parts (head, torso, upper arms, forearms, hands,
upper legs, shins, feet) driven by a **standard `Skeleton3D`** with Z-locked
bones. Bones have full weight but drive sprite node transforms (position + Z
rotation) instead of vertex deformation. Animations are authored in Blender
using the same pipeline as 3D characters — the only difference is that bones
are constrained to Z rotation and XY translation in the Blender rig.

This sits between the existing types:

| Type | Visual | Bone deformation | Animation pipeline |
|---|---|---|---|
| `3d` | 3D mesh + skeleton | Vertex skinning (XYZ) | Blender rig -> `.glb` -> `AnimationPlayer` + `Skeleton3D` |
| `puppet` | 2D part sprites + `Skeleton3D` | Sprite transform only (Z rot + XY pos) | Blender Z-locked rig -> `.glb` -> `AGSAnimationPlayerPuppet` maps bones to sprites |
| `2d` | Single sprite sheet | None | Sprite sheet frame selection |

### What it would look like

Classic examples: *South Park*, *Broken Sword*, *Grim Fandango*. Each body
part is a hand-drawn sprite placed at a bone's position. When the character
walks, the `AnimationPlayer` drives the `Skeleton3D` poses; the puppet runtime
reads each bone's transform and applies only its Z rotation and XY translation
to the corresponding `Sprite3D` child -- producing articulated motion without
any mesh deformation.

### Proposed skeleton hierarchy

```
root  (origin -- feet on floor)
└── torso
    ├── head
    │   └── hat  (optional accessory slot bone)
    ├── upper_arm_l
    │   └── forearm_l
    │       └── hand_l
    ├── upper_arm_r
    │   └── forearm_r
    │       └── hand_r
    ├── upper_leg_l
    │   └── shin_l
    │       └── foot_l
    └── upper_leg_r
        └── shin_r
            └── foot_r
```

Bone names are the mapping keys between the `Skeleton3D` and the `Sprite3D`
child nodes. Each `Sprite3D` rests at its bone's rest-pose world offset.

### `.agchar` additions

```
Character "hero" {
    display_name = "Hero"
    type         = "puppet"

    mesh = "characters/hero/hero.glb"   # Skeleton3D + AnimationPlayer clips

    parts = {
        torso       = { sprite = "assets/sprites/hero/torso.png",     z_order = 0  }
        head        = { sprite = "assets/sprites/hero/head.png",      z_order = 1  }
        upper_arm_l = { sprite = "assets/sprites/hero/arm_upper.png", z_order = -1 }
        forearm_l   = { sprite = "assets/sprites/hero/arm_lower.png", z_order = -1 }
        hand_l      = { sprite = "assets/sprites/hero/hand.png",      z_order = -1 }
        # ... etc
    }

    animations = {
        idle = "Idle"    # NLA clip names in the .glb
        walk = "Walk"
        talk = "Talk"
    }
}
```

No custom animation format. The `.glb` carries the skeleton and all animation
clips exactly as for `3d` characters.

### Direction variants

Sprite parts can swap to direction-specific art the same way as the `2d` type:

```
parts = {
    head = {
        sprites = {
            S = "head_front.png"
            N = "head_back.png"
            E = "head_side.png"    # mirrored for W via Sprite3D.flip_h
        }
        z_order = 1
    }
}
```

The puppet runtime selects the sprite variant based on the movement direction
(same 4-way/8-way quantization as `AGSAnimationPlayer2D`), then lets the
skeleton drive the rotation on top of the selected sprite.

### Godot implementation

**Scene structure generated by `ag build`:**

```
AGSCharacterPuppet  (root -- extends AGSCharacterBase)
  script = res://.engine/runtime/ags_character_puppet.gd
  Skeleton3D                      <- from .glb (bones only, no mesh)
  AnimationPlayer                 <- from .glb (drives Skeleton3D poses)
  CollisionShape3D                <- CapsuleShape3D as usual
  [Sprite3D "torso"]              <- positioned at bone rest offset
  [Sprite3D "head"]
  [Sprite3D "upper_arm_l"]
  ... (one Sprite3D per part, named to match bone names)
```

**`AGSAnimationPlayerPuppet` (extends `AGSAnimationPlayerBase`):**

- Holds a reference to the `Skeleton3D` and a `Dictionary` mapping bone
  names to `Sprite3D` nodes.
- Each `_physics_process` frame:
  1. `AnimationPlayer` advances and updates `Skeleton3D` bone poses (standard
     Godot behaviour -- no custom code needed here).
  2. `AGSAnimationPlayerPuppet` iterates the bone-to-sprite map: reads each
     bone's world XY position and Z rotation from
     `Skeleton3D.get_bone_global_pose(i)` and writes them to the corresponding
     `Sprite3D` node's `position` (X and Y only) and `rotation.z`.
     The Z depth component of bone position is discarded (all parts coplanar).
- Z-ordering: applied once at setup via `Sprite3D.render_priority` from the
  `z_order` field in `.agchar`. Not re-evaluated per frame.
- Billboard: the root `AGSCharacterPuppet` node faces the camera each frame
  via `look_at` with Y-axis locked. Individual `Sprite3D` nodes do **not**
  have individual billboard enabled -- they inherit root orientation.

**What the bones affect and what they ignore:**

| Bone transform component | Applied to sprite? | Notes |
|---|---|---|
| Position X, Y | Yes | Drives sprite world XY position |
| Position Z | No | Discarded -- all parts stay coplanar |
| Rotation Z | Yes | Drives sprite Z rotation |
| Rotation X, Y | No | Locked to zero in Blender rig; ignored in runtime |
| Scale | Optional | Useful for squash-and-stretch if needed |

### Blender workflow

Uses the same character export operator (T-BL10) as 3D characters. The only
authoring difference is bone constraints in the Blender rig:

- Each bone has a **Limit Rotation** constraint: X locked (0 to 0 deg),
  Y locked (0 to 0 deg), Z free.
- Each bone has a **Limit Location** constraint: Z locked (0 to 0); X and Y free.
- NLA tracks are authored as normal. The exporter does not need to know the
  rig is a puppet rig -- it exports a full `.glb` with `Skeleton3D` and
  `AnimationPlayer` as always.
- The `Sprite3D` children are **not** in Blender. They are added by `ag build`
  when it reads the `parts` block from `.agchar` and pairs each part name with
  a matching bone name.

### AG Studio

**Character editor additions:**
- Part list panel: add/remove parts, assign sprite files per part, set `z_order`.
- Bone mapping panel: reads bone names from the `.glb`; auto-maps parts where
  bone name matches part name; shows unmatched bones and unmatched parts.
- Direction sprite editor: per-part, per-direction sprite assignment (front/
  back/side sprites).

**Puppet animation viewer:**
- Assembles the puppet from `.agchar` parts at rest pose using bone offsets
  from the `.glb`.
- Plays back `AnimationPlayer` clips exactly as the runtime would.
- Direction selector switches sprite variants while the animation plays.
- No separate keyframe editor -- animation is always authored in Blender.

### Risks and open questions

- **`Skeleton3D` without mesh**: Godot's `Skeleton3D` is normally paired with
  a `MeshInstance3D`. Using it skeleton-only (no skinned mesh) is supported but
  this pattern needs a small Godot prototype to verify that
  `get_bone_global_pose()` returns correct world-space transforms when no mesh
  is attached.
- **Coplanarity under steep cameras**: same constraint as `2d` type -- the
  billboard orientation exposes top edges of sprites at steep camera angles.
  The same editor camera warning (W1 from F12 in editor-milestone.md) applies.
- **Performance**: 14+ `Sprite3D` nodes plus `Skeleton3D` pose reads per
  character per frame. Profile at 4 concurrent puppet characters before
  committing.
- **Bone-to-sprite pivot alignment**: the `Sprite3D` position tracks the bone
  world position. The sprite's visual joint centre in the art must match the
  bone head position in the Blender rest pose. This requires disciplined
  rigging -- document as a hard convention for artists.

### Promotion criteria

Promote to a full implementation milestone when:

1. A concrete game needs puppet-style characters.
2. The skeleton-only `Skeleton3D` pose extraction is verified by a small Godot prototype.
3. The coplanarity limit is acceptable for the target camera style.
4. Performance is profiled at realistic character counts (3-4 on screen).
